# Socratic Explorer — Cloudflare 통합 설계

상태: 구현 전 검토용. 사용자가 승인한 결정은 Cloudflare 통합과 기존 레포의 새 앱 전환이다. 아래 세부 구현은 작성자의 제안이다.

## 목적과 원칙
대학교 과제용 단일 사용자 앱. AI는 사용자의 문제나 결론을 대신 정하지 않는다. 문답은 기본적으로 주요 질문 하나를 생성하고 자체 검토한다. 사용자의 명시적 탐색 선언과 실행 요청만이 조사를 시작한다. 결론 없이 중단·재개할 수 있다. 기존 설계안의 20개 기능 모두 유지한다.

## 선택한 접근
1. React + Vite, Pages Functions, D1 통합: 기존 Git 연결 Pages 배포 활용, 운영 지점 하나. Python 코드를 사용하는 대신 서버 JavaScript와 Cloudflare 실행 제약을 따른다. 사용자 선택.
2. React Pages + 별도 FastAPI/SQLite 서버: 원래 기술을 유지하지만 별도 서버·배포·인증·CORS가 필요하여 선택하지 않았다.

## 구조와 배포
- frontend/: React + Vite + Tailwind, React Flow, react-markdown + remark-gfm, 코드 문법 강조 및 복사.
- functions/api/: Pages Functions의 세션·메시지·탐색·관계 API. 공유 서버 모듈은 별도 server/ 경로에 둬 Pages 라우트로 노출하지 않는다.
- migrations/: D1 스키마와 순차 migration.
- tests/: 상태 전이·LLM 어댑터·인증·데이터 보존 테스트.
- 루트 package.json과 lockfile로 도구 버전을 고정한다. 빌드 출력은 dist, Pages 빌드 명령은 npm run build. Git 연결 프로젝트의 실제 이름은 기존 설정을 확인해 유지한다. 원격 프로젝트 이름을 추측해 변경하지 않는다.
- 기존 public/index.html과 템플릿 API를 새 앱으로 교체하고 README·AGENTS를 새 요구에 맞춘다. 입력 비저장 규칙은 명시적 요구인 개인 D1 저장으로 대체하되 비밀값과 개인 데이터의 Git 커밋·입력 로그 금지를 유지한다.
- Windows: Node LTS, npm ci, Vite 개발 화면과 Wrangler Pages 통합 실행, 로컬 D1 migration. Python과 Cloudflare AI 바인딩은 불필요하다.
- 원격 D1 생성·바인딩, 원격 migration, Pages 빌드 설정과 Access 설정은 별도 배포 절차에 명시한다. 로컬 DB와 원격 DB를 구분한다. 현재 작업은 구현·검증이며 Git push와 운영 배포는 별도 사용자 요청에 따른다.

## 단일 사용자와 접근 제한
공개 페이지에서도 개인 데이터는 API 인증 없이 읽거나 변경할 수 없다. Cloudflare Access로 본인 이메일 접근을 제한하고, API도 Access JWT의 서명·issuer·audience·expiry와 허용 이메일을 검증한다. 공개 JWKS만 사용하고 제공된 이메일 헤더만 신뢰하지 않는다. 원격 환경은 설정 누락 시 거부한다. 브라우저 변경 요청에는 Origin 검증을 적용한다. 프리뷰도 같은 정책 또는 접근 거부를 적용한다. 로컬 인증 우회는 명시적 로컬 설정 및 loopback 환경에서만 가능하고 배포 환경에서는 금지한다. Access 팀 도메인·audience·허용 이메일은 사용자의 Cloudflare 설정 단계에서 필요하며 Git에 개인 이메일을 넣지 않는다. Access 비용·계정 기능 가용성은 배포 때 확인한다.

## 문답과 기록
세션 생성·선택·삭제, 메시지 자동 저장, 이전 맥락 전달, 질문 자체 검토, 질문 재생성, 발언 돌아보기, 중단·재개를 지원한다. 중단은 사용자 제어 상태이며 결론 여부를 AI 판정값으로 저장하지 않는다. 설명·사실 확인 요청에는 필요한 답변을 허용한다.
메시지 편집은 삭제될 후속 메시지와 연관 조사·관계의 영향 범위를 먼저 표시하고 확인 후 수행한다. 수정 시 세션 revision을 증가시키고 이전 revision의 지연 응답은 저장하지 않는다. 재생성은 마지막 AI 응답만 교체하는 것을 기본으로 하며 그 이후 발언이 있으면 동일한 영향 확인 절차를 적용한다. 실패해도 기존 응답은 성공한 대체 응답 저장 전까지 보존한다. 사용자 입력은 서버 로그에 기록하지 않는다.

## 데이터
D1에 sessions, messages, research_runs, research_steps, sources, research_followups, graph_edges, graph_rejections, operations를 저장한다. 발언 원문·사용자 탐색 선언과 AI 해석은 별도 필드다. 외래키·트랜잭션·revision 조건부 쓰기로 불일치를 방지한다. 모든 API는 단일 소유자 범위를 확인한다. 메시지·그래프·조사 상태는 새로고침 시 복구된다. SQLite 파일·로컬 상태·.env·.dev.vars와 키는 Git에서 제외한다.

## 탐색 실행
명시적 실행 후 3~5개 하위 질문을 생성한다. 하나의 긴 요청 대신 실제 처리 단계별 짧은 요청으로 실행한다: 분해 → 질문별 검색 및 분석 → 통합. 각 단계 시작·성공·실패를 D1에 저장하고 UI는 저장된 실제 상태를 표시한다. 검색과 분석이 하나의 제공업체 호출에서 실행되면 분리된 가짜 진행률을 만들지 않고 '검색·분석 중'으로 표시한다.
클라이언트가 활성 작업을 진행시키며 탭 종료 시 현재 요청 완료 후 멈출 수 있다. 다시 열면 상태를 읽고 재개한다. 항상 백그라운드로 완료되는 기능은 범위 밖이다. 단계 lease와 idempotency key로 중복 실행·중복 저장을 억제한다. 외부 호출의 timeout 이후 원격 처리 여부는 확정할 수 없으므로 재시도 시 추가 사용 가능성을 알린다. 재시도는 횟수와 대기 시간을 제한한다. 하위 질문 실패는 다른 결과를 지우지 않는다. 부분 성공과 완료·실패를 구별한다.
최종 화면은 선언 원문, 하위 질문별 결과·출처·불확실성, 종합 답변과 활용 방향을 표시한다. 추가 질문은 기존 결과를 근거로 답하고 신규 정보 필요 시 명시적으로 검색 작업을 생성한다. 문답 복귀는 기존 문답을 보존한다.

## OpenRouter
서버 공통 어댑터를 사용하고 문답·분해·탐색·관계 프롬프트를 분리한다. 기본 모델 후보는 사용자가 선택한 Nemotron 3 Ultra 무료 엔드포인트다. 정확한 모델 ID는 현재 공식 목록으로 검증하기 전 하드코딩하지 않는다. OPENROUTER_API_KEY는 서버 secret, LLM_MODEL과 검색 설정은 환경별 설정으로 관리한다. 키는 프런트 번들·에러·로그에 포함하지 않는다. Gemma 계열과 자동 유료 모델 전환은 사용하지 않는다.
텍스트 문답과 구조 JSON 출력·실제 출처 반환을 개별 검증한다. 구조 JSON은 서버 스키마로 검증하며 깨진 응답을 성공으로 저장하지 않는다. 검색은 OpenRouter 지원 검색 도구/플러그인 어댑터를 통해 실행하되 현재 지원 방식과 요금을 검증해야 한다. 모델이 생성한 임의 URL을 검색 근거로 취급하지 않고 제공업체가 반환한 검색 자료/annotations를 출처로 추출한다. 잘못된 source ID 참조를 거부한다. 실제 자료를 받지 못하면 unsupported/failed로 처리한다. 무료 추론과 별도 검색 요금은 구분하고, 검색은 설정에서 명시적으로 허용한 경우에만 실행한다. 제공업체 과금·할당량을 통제할 수 있다고 주장하지 않는다.
문답·관계 분석이 검색 기능과 독립적으로 동작한다. 인증 실패·한도·연결·timeout·미지원 기능·응답 형식 오류를 구분하고 안전한 오류와 재시도를 제공한다. 실제 API 검증은 키와 확인된 모델 ID가 필요하며 모의 테스트와 구별한다.

## 사고 지도와 렌더링
노드는 사용자 메시지 원문에 대응한다. AI는 명확한 관계만 제안한다. 관계 유형은 구체화·근거·예시·보완·대조·질문. 서버에서 같은 세션의 유효 메시지 ID와 허용 유형을 검사한다. 사용자 관계 수정·추가를 보호하고, 삭제 tombstone으로 AI가 같은 관계를 재생성하지 못하게 한다. 새로고침 후에도 보호된다. 노드 원문 확인과 관계 추가·수정·삭제를 지원한다. 초기 레이아웃은 단순하게 구현한다.
Markdown 원시 HTML을 실행하지 않고 안전한 링크 프로토콜만 허용한다. 코드 하이라이트·복사·가로 스크롤을 제공한다. 모바일에서는 사이드바·지도·결과를 좁은 화면에 맞춘다. 로딩·빈 화면·실패·재시도를 구분하고 전송 중 중복 제출을 방지한다.

## 검증과 완료 조건
빌드, API/데이터·revision·인증 테스트, Pages 로컬 통합 HTTP, 브라우저 흐름을 검증한다. 원 설계의 6개 시나리오와 20개 기능을 추적한다. 메시지 편집 확인 취소·확정, 재생성 실패 보존, 부분 조사 실패, 새로고침 재개, 사용자 그래프 수정 보호, 인증 없는 API 거부, HTML/링크 안전 렌더링을 포함한다.
모의 제공업체 테스트는 통합 로직만 증명한다. 실제 모델의 다회 문답·중립성, 실제 검색 출처와 후속 질문은 OpenRouter 실호출로 별도 검증한다. 원격 D1·Access·Pages는 사용자의 설정과 배포 후 별도 smoke test로 확인한다. 미실행·실패를 통과로 표시하지 않는다.

## 비목표와 미확정 사항
계정 관리 UI·다중 사용자·고급 그래프 알고리즘·다중 에이전트·항상 실행되는 조사 worker는 제외한다. 시각 디자인·API 세부 경로·스키마 세부 타입·라이브러리 버전은 구현자가 결정한다. 사용자에게 필요한 결정은 검색 추가 요금 허용 여부이며, 미허용 상태에서도 문답·기록·지도를 구현할 수 있다. Cloudflare 계정 식별자·D1 ID·Access 값·OpenRouter 키는 배포 시 설정하고 임의로 만들지 않는다.

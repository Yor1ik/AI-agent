# Socratic Explorer — Cloudflare 통합 설계

상태: 구현 전 검토용. 사용자가 승인한 결정은 Cloudflare 통합과 기존 레포의 새 앱 전환이다. 아래 세부 구현은 작성자의 제안이다.

## 목적과 원칙
대학교 과제용 단일 사용자 앱. AI는 사용자의 문제나 결론을 대신 정하지 않는다. 문답은 기본적으로 주요 질문 하나를 생성하고 자체 검토한다. 사용자의 명시적 탐색 선언과 실행 요청만이 조사를 시작한다. 결론 없이 중단·재개할 수 있다. 기존 설계안의 20개 기능 모두 유지한다.

## 선택한 접근
1. React + Vite, Pages Functions, D1 통합: 기존 Git 연결 Pages 배포 활용, 운영 지점 하나. Python 코드를 사용하는 대신 서버 JavaScript와 Cloudflare 실행 제약을 따른다. 사용자 선택.
2. React Pages + 별도 FastAPI/SQLite 서버: 원래 기술을 유지하지만 별도 서버·배포·인증·CORS가 필요하여 선택하지 않았다.

## 구조와 배포
- frontend/: React + Vite + Tailwind, React Flow, react-markdown + remark-gfm, 코드 문법 강조 및 복사.
- functions/api/: Pages Functions의 세션·메시지·탐색·관계 API. 공유 서버 모듈은 별도 server/ 경로에 둬 Pages 라우트로 노출하지 않는다.
- migrations/: D1 스키마와 순차 migration.
- tests/: 상태 전이·LLM 어댑터·인증·데이터 보존 테스트.
- 루트 package.json과 lockfile로 도구 버전을 고정한다. 빌드 출력은 dist, Pages 빌드 명령은 npm run build. Git 연결 프로젝트의 실제 이름은 기존 설정을 확인해 유지한다. 원격 프로젝트 이름을 추측해 변경하지 않는다.
- 기존 public/index.html과 템플릿 API를 새 앱으로 교체하고 README·AGENTS를 새 요구에 맞춘다. 입력 비저장 규칙은 명시적 요구인 개인 D1 저장으로 대체하되 비밀값과 개인 데이터의 Git 커밋·입력 로그 금지를 유지한다.
- Windows: Node LTS, npm ci, Vite 개발 화면과 Wrangler Pages 통합 실행, 로컬 D1 migration. Python과 Cloudflare AI 바인딩은 불필요하다.
- 원격 D1 생성·바인딩, 원격 migration, Pages 빌드 설정과 Access 설정은 별도 배포 절차에 명시한다. 로컬 DB와 원격 DB를 구분한다. 현재 작업은 구현·검증이며 Git push와 운영 배포는 별도 사용자 요청에 따른다.

## 단일 사용자와 접근 제한
공개 페이지에서도 개인 데이터는 API 인증 없이 읽거나 변경할 수 없다. Cloudflare Access로 본인 이메일 접근을 제한하고, API도 Access JWT의 서명·issuer·audience·expiry와 허용 이메일을 검증한다. 공개 JWKS만 사용하고 제공된 이메일 헤더만 신뢰하지 않는다. 원격 환경은 설정 누락 시 거부한다. 브라우저 변경 요청에는 Origin 검증을 적용한다. 프리뷰도 같은 정책 또는 접근 거부를 적용한다. 로컬 인증 우회는 명시적 로컬 설정 및 loopback 환경에서만 가능하고 배포 환경에서는 금지한다. Access 팀 도메인·audience·허용 이메일은 사용자의 Cloudflare 설정 단계에서 필요하며 Git에 개인 이메일을 넣지 않는다. Access 비용·계정 기능 가용성은 배포 때 확인한다.

## 문답과 기록
세션 생성·선택·삭제, 메시지 자동 저장, 이전 맥락 전달, 질문 자체 검토, 질문 재생성, 발언 돌아보기, 중단·재개를 지원한다. 중단은 사용자 제어 상태이며 결론 여부를 AI 판정값으로 저장하지 않는다. 설명·사실 확인 요청에는 필요한 답변을 허용한다. 이 경우에도 검색은 검색 허용 설정과 사용자의 명시적 요청이 모두 있을 때만 실행하고, 검색 없이 확인할 수 없는 최신 사실은 확인 불가로 표시한다.
메시지 편집은 삭제될 후속 메시지와 연관 조사·관계의 영향 범위를 먼저 표시하고 확인 후 수행한다. 수정 시 세션 revision을 증가시키고 이전 revision의 지연 응답은 저장하지 않는다. 재생성은 같은 사용자 발언과 맥락을 유지하고 표현이나 검토 유형만 바꾸며 새로운 전제나 목표를 도입하지 않는다. 마지막 AI 응답만 교체하는 것을 기본으로 하며 그 이후 발언이 있으면 동일한 영향 확인 절차를 적용한다. 실패해도 기존 응답은 성공한 대체 응답 저장 전까지 보존한다. 사용자 입력은 서버 로그에 기록하지 않는다.

## 데이터
D1에 sessions, messages, research_runs, research_steps, sources, graph_edges, graph_rejections를 저장한다. 탐색 후속 문답은 messages에 모드와 탐색 참조를 부여해 저장하고 별도 operations 테이블은 두지 않는다. 발언 원문·사용자 탐색 선언과 AI 해석은 별도 필드다. D1은 대화형 BEGIN/COMMIT 트랜잭션 대신 db.batch()의 원자적 실행을 사용한다. 편집은 서버에서 생성한 변경 식별자와 예상 revision으로 UPDATE sessions ... WHERE revision = ?를 실행하고, 같은 batch의 모든 후속 변경도 해당 변경 식별자 소유 조건에 종속시킨다. UPDATE가 0행이어도 batch가 자동 중단되지 않으므로 모든 삭제·삽입에도 조건을 적용하고 meta.changes로 충돌을 판정한다. revision을 먼저 조회했다는 이유만으로 무조건 삭제하지 않는다. 연결 ID는 서버에서 미리 생성한다. 외래키 순서 또는 cascade를 우선 사용하고, 필요한 경우에만 같은 batch에서 defer_foreign_keys를 검토한다. messages(session_id, position), research_runs(session_id), research_steps(run_id, position), sources(step_id), graph_edges(session_id) 등에 인덱스를 둔다. 연관 삭제는 조건부 문장들을 한 batch로 묶는다. batch를 썼다는 이유로 쿼리 수가 항상 1로 계산된다고 가정하지 않고 내부 SQL 문장과 실제 플랫폼 한도를 확인한다. 모든 API는 단일 소유자 범위를 확인한다. 메시지·그래프·조사 상태는 새로고침 시 복구된다. SQLite 파일·로컬 상태·.env·.dev.vars와 키는 Git에서 제외한다.

## 탐색 실행
명시적 실행 후 사용자 선언에서 직접 도출되는 하위 질문만 생성한다. 하위 질문 수의 최소·최대·고정 개수를 두지 않는다. 숫자를 맞추기 위해 질문을 추가하거나 의미가 다른 질문을 합치지 않고 중복은 제거한다. 실용적으로 분해할 수 없으면 원래 질문 하나를 조사한다. 생성된 질문 목록과 예상 호출량을 보여주고 사용자가 실행·일시정지·재개를 제어한다. API 출력 길이·실행 시간·할당량 한계는 존재하므로 잘린 응답을 정상 완료로 저장하지 않으며, 기술적 제한을 질문 개수 제한으로 대체하지 않는다. 하나의 긴 요청 대신 실제 처리 단계별 짧은 요청으로 실행한다: 분해 → 질문별 검색 및 분석 → 통합. 각 단계 시작·성공·실패를 D1에 저장하고 UI는 저장된 실제 상태를 표시한다. 검색과 분석이 하나의 제공업체 호출에서 실행되면 분리된 가짜 진행률을 만들지 않고 '검색·분석 중'으로 표시한다.
클라이언트가 활성 작업을 진행시키며 탭 종료 시 현재 요청 완료 후 멈출 수 있다. 다시 열면 상태를 읽고 재개한다. 항상 백그라운드로 완료되는 기능은 범위 밖이다. 별도 lease 시스템과 idempotency key 저장소는 만들지 않는다. 탐색마다 활성 단계 하나만 허용하고 상태와 revision을 포함한 조건부 UPDATE로 실행권을 얻은 요청만 외부 호출한다. 두 탭에서 동시 요청해도 한 요청만 실행한다. 시간 초과 등으로 running 상태가 남으면 사용자가 확인 후 재시도 상태로 전환하며, 이전 실행의 단계 revision과 일치하지 않는 지연 응답은 저장하지 않는다. 상태 검사 후 무조건 실행하는 방식은 금지한다. 외부 호출의 timeout 이후 원격 처리 여부는 확정할 수 없으므로 재시도 시 추가 사용 가능성을 알린다. 재시도는 횟수와 대기 시간을 제한한다. 하위 질문 실패는 다른 결과를 지우지 않는다. 부분 성공과 완료·실패를 구별한다. 활성 화면에서만 보수적인 간격과 backoff로 상태를 조회하고 숨겨진 탭과 종료 상태에서는 폴링을 중지한다. 단계 실행 응답에 최신 상태를 포함해 불필요한 추가 조회를 줄인다.
최종 화면은 선언 원문, 하위 질문별 결과·출처·불확실성, 종합 답변과 활용 방향을 표시한다. 추가 질문은 기존 결과를 근거로 답하고 신규 정보 필요 시 명시적으로 검색 작업을 생성한다. 문답 복귀는 기존 문답을 보존한다.

## OpenRouter
서버 공통 어댑터를 사용하고 문답·분해·탐색·관계 프롬프트를 분리한다. 기본 모델 후보는 사용자가 선택한 Nemotron 3 Ultra 무료 엔드포인트다. 정확한 모델 ID와 무료 엔드포인트 존재 여부는 현재 공식 목록으로 검증하기 전 확정하지 않는다. 검증한 고정 모델 ID를 사용하고 openrouter/free 같은 무작위 모델 라우터는 사용하지 않는다. 테스트 기록에는 모델 ID를 남기되 사용자 발언은 로그에 남기지 않는다. 무료 제공업체의 데이터 보관·학습 허용 정책과 계정의 무료/유료 데이터 설정을 개별 확인한다. 적합한 무료 엔드포인트가 없으면 기능 지원 불가를 명시하고 다른 모델 선택은 사용자와 협의한다. OPENROUTER_API_KEY는 서버 secret, LLM_MODEL과 검색 설정은 환경별 설정으로 관리한다. 키는 프런트 번들·에러·로그에 포함하지 않는다. Gemma 계열과 자동 유료 모델 전환은 사용하지 않는다.
텍스트 문답과 구조 JSON 출력·실제 출처 반환을 개별 검증한다. 구조 JSON은 서버 스키마로 검증하며 깨진 응답을 성공으로 저장하지 않는다. 검색은 OpenRouter 지원 검색 도구/플러그인 어댑터를 통해 실행하되 현재 지원 방식과 요금을 검증해야 한다. 모델이 생성한 임의 URL을 검색 근거로 취급하지 않고 제공업체가 반환한 검색 자료/annotations를 출처로 추출한다. 잘못된 source ID 참조를 거부한다. 실제 자료를 받지 못하면 unsupported/failed로 처리한다. 무료 추론과 별도 검색 요금은 구분하고, 검색은 설정에서 명시적으로 허용한 경우에만 실행한다. 제공업체 과금·할당량을 통제할 수 있다고 주장하지 않는다.
문답·관계 분석이 검색 기능과 독립적으로 동작한다. 문답은 자체 검토를 같은 호출에 포함해 기본 1회 호출로 처리하고, 관계 분석은 메시지마다 자동 호출하지 않는다. 사고 지도 탭을 처음 열거나 사용자가 갱신 버튼을 누를 때만 수행하며 변경이 없으면 저장된 결과를 사용한다.
무료 호출 한도는 계정·제공업체의 실제 응답을 기준으로 처리한다. 사용자 검토에서 제시한 기준은 분당 20회, 일 50회, 누적 크레딧 구매 10달러 이상 시 일 1,000회이며 실패한 호출도 포함된다. 이 수치는 공식 문서 재확인 전 검증 대기 정보로 표시하고 코드 상수로 확정하지 않는다. 충전·구매는 사용자가 결정하며 앱이 수행하지 않는다. 하위 질문 n개인 탐색은 기본 n+2회(분해·질문별 조사·통합), 재시도·재생성·추가 검색·관계 갱신은 별도 호출이다.
429 속도 제한과 확인된 일일 한도 소진을 구분하되 오류 정보가 불충분하면 일반 한도 오류로 표시하고 원인을 추측하지 않는다. Retry-After가 있으면 따른다. GET /api/v1/key가 실제 제공하는 필드를 검증하고, 달러 크레딧 잔액이나 금액 한도를 무료 모델의 남은 호출 횟수로 바꾸지 않는다. 제공업체가 호출 잔여량을 제공할 때만 확정 잔여량으로 표시한다. 그 외에는 이 앱의 호출 시도 수와 계산 근거를 표시하며 외부 사용·실패·리셋 시각 때문에 정확한 계정 잔여량을 알 수 없다고 명시한다. 키 메타데이터 전체나 비밀값을 브라우저에 반환하지 않는다. 인증 실패·한도·연결·timeout·미지원 기능·응답 형식 오류를 구분하고 안전한 오류와 재시도를 제공한다. 실제 API 검증은 키와 확인된 모델 ID가 필요하며 모의 테스트와 구별한다.

## 사고 지도와 렌더링
노드는 사용자 메시지 원문에 대응한다. AI는 명확한 관계만 제안하고 발언 원문에 없는 심리·의도·성향을 관계명이나 설명으로 단정하지 않는다. 관계 유형은 구체화·근거·예시·보완·대조·질문. 서버에서 같은 세션의 유효 메시지 ID와 허용 유형을 검사한다. 지도 snapshot과 수동 변경 요청에는 클라이언트가 확인한 revision을 포함해 다른 탭의 새 수정·삭제를 덮어쓰지 않는다. 기존 관계 수정과 명시적 새 연결을 구분한다. 사용자 관계 수정·추가를 보호하고, 삭제 tombstone으로 AI가 같은 관계를 재생성하지 못하게 한다. 새로고침 후에도 보호된다. 노드 원문 확인과 관계 추가·수정·삭제를 지원한다. 초기 레이아웃은 단순하게 구현한다.
Markdown 원시 HTML을 실행하지 않고 안전한 링크 프로토콜만 허용한다. 코드 하이라이트·복사·가로 스크롤을 제공한다. 모바일에서는 사이드바·지도·결과를 좁은 화면에 맞춘다. 로딩·빈 화면·실패·재시도를 구분하고 전송 중 중복 제출을 방지한다.

## 검증과 완료 조건
빌드, API/데이터·revision·인증 테스트, Pages 로컬 통합 HTTP, 브라우저 흐름을 검증한다. 원 설계의 6개 시나리오와 20개 기능을 추적한다. 메시지 편집 확인 취소·확정, 재생성 실패 보존, 부분 조사 실패, 두 탭 동시 편집·탐색 실행, stale revision에서 후속 삭제가 일어나지 않음, 무료 호출 제한과 알 수 없는 잔여량 표시, 새로고침 재개, 사용자 그래프 수정 보호, 인증 없는 API 거부, HTML/링크 안전 렌더링을 포함한다.
모의 제공업체 테스트는 통합 로직만 증명한다. 실제 모델의 다회 문답·중립성, 실제 검색 출처와 후속 질문은 OpenRouter 실호출로 별도 검증한다. 원격 D1·Access·Pages는 사용자의 설정과 배포 후 별도 smoke test로 확인한다. 미실행·실패를 통과로 표시하지 않는다.

## 비목표와 미확정 사항
계정 관리 UI·다중 사용자·고급 그래프 알고리즘·다중 에이전트·항상 실행되는 조사 worker는 제외한다. 시각 디자인·API 세부 경로·스키마 세부 타입·라이브러리 버전은 구현자가 결정한다. 사용자는 OpenRouter 크레딧 10달러 충전 사실을 알리고 검색 추가 비용을 허용했다. 검색 사용을 활성화할 수 있으며 앱에서 중단·재개할 수 있다. 잔액의 충분함이나 사용 가능 횟수는 보장하지 않는다. 추가 충전·자동 유료 모델 전환은 승인에 포함되지 않는다. Cloudflare 계정 식별자·D1 ID·Access 값·OpenRouter 키는 배포 시 설정하고 임의로 만들지 않는다.

## 외부 검토와 확인 상태 (2026-11-05)
외부 검토의 호출 절약·D1 batch·인덱스·관계 분석 지연 실행·단일 활성 단계 제안을 반영했다. 사용자 최신 지시에 따라 하위 질문 개수는 제한하지 않는다. 공식 OpenRouter·Cloudflare 문서 요청은 환경 네트워크 정책의 403으로 차단되어, 현재 한도 숫자·적용 날짜·batch 쿼리 계수·키 API 필드는 독립 검증하지 못했다. D1 읽기·쓰기·invocation 한도와 Pages/Workers 공유 요청 한도는 구현·배포 시 공식 최신 문서로 확인하고 하드코딩된 보장으로 사용하지 않는다. 기술 설계의 원자성·서버 스키마 검증은 로컬 런타임 테스트로 확인한다.
공식 확인 대상: https://developers.cloudflare.com/d1/worker-api/d1-database/ , https://developers.cloudflare.com/d1/platform/limits/ , https://developers.cloudflare.com/d1/platform/pricing/ , https://openrouter.ai/docs/api-reference/limits , https://openrouter.ai/api/v1/key .

구현 검토 보강: sources 교체·step 결과·실행권 해제는 하나의 조건부 D1 batch로 확정한다. sessions 테이블 자체의 UPDATE는 EXISTS 하위 조건만 쓰지 않고 대상 id·owner_id·변경 식별자를 바깥 WHERE에서 직접 제한한다. 실행 중인 탭도 실제 활성 단계를 조회하며 낮은 revision의 늦은 응답으로 화면을 되돌리지 않는다.
